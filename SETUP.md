# Настройка серверной части
Для запуска серверной части вы можете воспользоваться контейнеризацией через **Docker**.

### Dockerfile
В **Dockerfile** уже изложена корректная настройка Docker-изображения. Вы можете ознакомиться с ним и запустить его как отдельный контейнер, либо (рекомендовано) использовать Docker Compose.

### docker-compose.yml
Воспользуйтесь командой `docker compose up -d --build` (единоразово, в дальнейшем `docker compose up -d`), чтобы запустить сервис в detached формате. Чтобы отслеживать его выполнение, вы можете прибегнуть к команде `docker compose logs -f`.

### Обратное проксирование
По умолчанию, согласно файлам настройки Docker, процесс uvicorn запустится на порте 6190 и будет доступен только локально. Для того чтобы сделать API публично доступным, вы можете:
- bind-ить API по адресу 0.0.0.0 (в **docker-compose.yml**), либо
- настроить reverse proxy (рекомендуется)

В демонстрационной версии (по адресу **tritoni.runderscore.com**) обратное проксирование настроено при помощи [Caddy](https://caddyserver.com/docs/):
```Caddyfile
tritoni.runderscore.com {
    reverse_proxy localhost:6190
}
```
Вы также можете воспользоваться любым другим веб-сервером или обратным прокси, например, **Nginx** или **Traefik**.

По окончании настройки обратного прокси, API будет доступен по адресу `https://<ваш адрес>/api/v1`.

# Настройка клиентской части
Чтобы собрать клиентскую часть, перейдите в директорию `web` и соберите **npm**-проект:
```bash
cd web
npm install
npm run make
```
При сборке на Windows, артефакт сборки будет находиться в `out/make/squirrel.windows/x64`.

Установить путь к API можно будет непосредственно внутри настроек работающего приложения (либо отредактировав значение по умолчанию программно перед сборкой).
